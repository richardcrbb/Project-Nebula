NEXTCLOUD

In this tutorial, you'll learn how to install Nextcloud using a Docker Compose file configured to store its data inside a dedicated Btrfs subvolume located on a subvolume in a separate partition of the same device. If you haven't completed the setup of those subvolumes yet, make sure to watch the previous tutorial (Important Data) linked in the sidebar of this website.

Mandatory

The requirement to run this instance is to follow the entire project guide, as this help you create the subvolumes we are going to use and the subnet we created using Tailscale, this allowed us to join our LAN and docker's subnet and access it from anywhere in the world.

Transfer Your Data

If you followed this entire guide, you must have a subvolume @nextcloud in your server, and a PC with a directory where your important data lays and connected to the same lan, copy your important data (Photos, Files, etc.) to the subvolume mount point of your server directly from your PC client using the scp tool.

From your server, change the permission of the subvolume directory:

sudo chown -R 1000:1000 /mnt/subvolumes/nextcloud

From your client, not your server, update with your info and run:


        
Keep in mind that the tailnet-vpn Docker network connects the containers within the same subnet, but it operates in isolation. This means you cannot 
            access your server directly from within the container. The container is isolated from your host machine. To transfer data or communicate with the 
            server, you need to use the LAN IP address of the host machine. Essentially, your PC must be on the same local network as the server in order to 
            transfer data.
        

        
Or you can install another node in your Server O.S. thus you can communicate from any node in your tailnet directly to the server, not a docker container.

    

    

        
Set up the Nextcloud project directory

        
Create and prepare the directory where your Nextcloud project will live. This folder will store your Docker Compose file and any configuration 
            related to your Nextcloud deployment. Make sure the directory is located inside the dedicated subvolume you created earlier, so that your data 
            and configuration persist independently from your operating system.

            
Create the directory for your Nextcloud configuration, then set the appropriate ownership and permissions for the @nextcloud subvolume.

            

            

    

    

        
Set Your Domain

        
With the help of your Pi-hole service, set a custom domain name to easily access your Nextcloud service, pointing to the next available IP in your 
            Tailnet VPN subnet, which is 10.10.10.4. For the purposes of this tutorial, we will use nextcloud.nube, but you 
            can choose any domain you prefer. If you decide to change this port—which is not recommended—make sure to update the compose.yaml file accordingly.

    WARNING
    
        
    In your Nextcloud web interface, make sure to save all important information in the external storage directory you configured earlier, as it is mounted 
            to your @nextcloud subvolume. This ensures your data remains persistent even if containers or volumes are deleted. You can always redeploy from a fresh 
            installation by following these instructions, and your data will still be intact. Later in this project, we will cover a full backup solution for the 
            entire SD3 partition. Once again, remember to store your data in your external storage directory.
